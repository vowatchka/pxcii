# ТЗ: `pxcii` — конвертер изображений в псевдографику

## 1. Назначение

Консольная утилита (с дополнительными режимами запуска), которая принимает на вход изображение и воспроизводит **то же самое изображение**, отрисованное спецсимволами (ASCII/Unicode-псевдографика). Не абстрактная стилизация, не «похожая картинка» — обратимое по смыслу отображение исходника в сетку символов.

Одна кодовая база, один исполняемый файл, три режима запуска.

## 2. Платформы

- **Windows**, **Linux**, **macOS** — все три обязательны
- x86_64 и arm64 (Apple Silicon)
- Поставка — один нативный бинарь, без рантайма и без системных зависимостей
- Полная сборка (десктоп + CLI + веб) — для пользовательских платформ; slim-сборка (CLI + веб) — для Docker/сервера

## 3. Поддерживаемые форматы

**Вход = выход.** 9 форматов, все — чистый Rust, без C-зависимостей и внешних библиотек:

`PNG` · `JPEG` · `WebP` · `GIF` · `BMP` · `TIFF` · `ICO` · `TGA` · `PNM`

Ограничения (приняты осознанно):

- WebP на выходе — только lossless
- ICO — не больше 256×256, при превышении ресайз с предупреждением
- GIF — только первый кадр, ≤256 цветов
- Мультикадровые/анимированные входы — берётся первый кадр, на выходе всегда статика
- JPEG на выходе допустим, но сопровождается подсказкой о потере качества глифов

**Вне области поддержки:** HEIC и AVIF (требуют C-библиотек), SVG (векторный), QOI (не популярен).

## 4. Режимы запуска

| Режим | Команда | Описание |
|---|---|---|
| **CLI** | `pxcii image.jpg` | Основной режим. По умолчанию печатает псевдографику в консоль |
| **Desktop** | `pxcii desktop` | Минимальное нативное окно |
| **Web** | `pxcii serve` | Локальный сервер, та же минималистичная страница в браузере |

Сабкоманды одного бинаря; GUI-подсистема инициализируется только в режиме `desktop`.

## 5. Функциональность

**Вывод по умолчанию:** консоль, цвета оригинала.

**Параметры:**

- цвет: оригинальные цвета (по умолчанию) / монохром
- сохранение в **текстовый файл** (любое расширение) или в **файл изображения** одного из 9 форматов
- ширина сетки в символах
- режим символов: ASCII / блоки / braille
- дизеринг
- коррекция пропорций знакоместа

**Desktop и Web — минимальный интерфейс:**

- выбрать изображение (диалог ФС / drag-and-drop)
- переключить цвет / монохром
- выбрать куда сохранить (текст или изображение)
- увидеть результат

Ничего сверх этого: без настроек профилей, без истории, без галерей.

## 6. Приватность и побочные эффекты

**Desktop и Web не сохраняют и не кэшируют входные изображения.** Запуск не влияет на файловую систему: не создаётся ни файлов, ни скрытых папок, ни конфигов, ни логов, ни временных файлов.

- весь пайплайн — в памяти: `&[u8]` → `Vec<u8>`/`String`
- единственная запись на диск — явное действие пользователя «Сохранить»
- настройки интерфейса не персистятся

## 7. API

### Rust

Библиотечный крейт с полным пайплайном: декодирование, рендер в сетку символов, вывод в ANSI/текст/растр, кодирование в 9 форматов. Те же вызовы используют CLI, desktop, web и Python-обёртка — поведение байт-в-байт идентично.

### Python

Пакет с wheels, статически содержащий Rust-ядро. **Python API — исключительно «open/save в коде»:**

- принять изображение (путь или байты)
- вернуть псевдографику (строка ANSI/текст) или изображение (байты)
- сохранить результат

**Python API не включает** режимы desktop, CLI и web-сервер. Обвязки (CLI-парсер, HTTP-сервер, GUI) для Python пишутся отдельно теми, кому это нужно — они не входят в поставку пакета.

## 8. Нефункциональные требования

- **Скорость**: обработка мегапиксельного изображения — доли секунды; серверный отклик без заметной задержки
- **Память**: минимальное потребление, без интерпретатора и рантайма в основе
- **Детерминизм**: одинаковый вход + одинаковые параметры = побайтово одинаковый выход на всех платформах (проверяется golden-тестами)
- **Ноль побочных эффектов** в desktop/web (см. п. 6)

## 9. Язык и стек

**Rust** — как единственный вариант, закрывающий все три режима одним бинарём без рантайма, с предсказуемой памятью и без C-зависимостей.

- ядро — pure Rust, без FFI
- GUI — нативный, без системного WebView и без кэшей
- веб — лёгкий HTTP-сервер, обработка потоковая, лимит размера тела запроса
- Python — отдельным крейтом-обёрткой, ядро при этом не меняется

## 10. Не-цели

- HEIC / AVIF / SVG / QOI
- анимация и многокадровый выход
- облако, база, история, аккаунты
- мобильные платформы
- конфигурируемые темы и плагины
